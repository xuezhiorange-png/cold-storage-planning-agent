# 参数化工程布置草案（未批准）

## 六类独立包络

1. PACKING_STATION_ENVELOPE：实际台体、机架、护罩、附件及输送连接。需选型总图，不是5.6×3.0。
2. OPERATOR_ENVELOPE：三人各自站位、动作、取放、脚腿空间及相互干涉。需任务和操作研究；人数不能换算为猜测人均面积。
3. MATERIAL_SUPPLY_ENVELOPE：包材补给、周转容器、废弃物/剔除物及现场缓冲。需容器外廓、频次和运送方式。
4. PRODUCT_OUTFEED_ENVELOPE：成品接取、输送、码放和出口缓存。不能默认与供料带重叠共用。
5. CIRCULATION_ENVELOPE：连续独立通行、门扇、人员到达及物流连接。需项目适用净宽/消防卫生等专业依据，不自行设数值。
6. CLEANING_MAINTENANCE_ENVELOPE：清洗、拆装、护罩开启、检修和器具空间。需要设备说明及停机程序。

来源E01要求适当生产/清洁检修空间；E02/E03说明操作与不同状态不能只看设备本体；E04/E07展示实际供料/出料/剔除和清洁组织。E05、E06只能用于说明设备体系差异，不是项目选型依据。完整限制见engineering-sources.json。

## 计算与状态

对候选行列及真实设备姿态，放置每个有来源的二维整数毫米包络。必须显式提供所有组件，未使用组件也需显式声明空集合；缺少组件或运行状态返回OWNER_INPUT_REQUIRED，不补默认尺寸。

正常生产时设备、三人动作、供料、出料和独立通行需要同时存在；临时缓存必须据周转周期和数量另列。清洁检修时可停止生产，但仍需保留工程要求的通行。只有审核通过的时序、互锁或停机条件，才允许不同状态使用同一空间。

离线工具以精确坐标并集给出占用面积，以 `max(x)-min(x)`、`max(y)-min(y)` 给出外包络；正面积重叠单独列为待审冲突，不能通过取max、求并集或总面积足够而自动通过。并集只是几何量，不是允许共享的证据；外包络中的空隙也不自动是合格通道。布局仍须验证连接性、门洞、作业可达性、消防卫生、清洁和物流冲突。草案工具不替代这些验证，永不输出功能PASS。

外围余量只能来自已审核且未被工位组件包含的独立需求，逐边添加，不能既包含在节距中又再次计入。建筑净内尺寸、墙/柱/保温及建筑外尺寸必须分开；现有P1C尺寸不能未经审核称为扣除设备/墙体后的净通道。

最终方法：有来源包装量→两班定员→峰值人数→需求台数→多个候选行列/朝向→真实包络/独立通道→各运行状态审核→房间净尺寸及建筑尺寸→面积及Portal物流验证。需另经Owner授权才能实现新版P1消费者。

## 不采用的捷径

- 不把16.8m²当设备面积乘台数。
- 不把8.0和7.6拆成未经证实的净通道。
- 不在长宽都乘1.1；也不把旧1.1当新版默认。
- 不以台位格数代替安装需求数；空格是否可作缓存需实际布置批准。
- 不以最低面积排名代替工艺、包材接口和人员到达审核。
- 不把既有封闭房间/Access PASS当成室内工位PASS。

PARAMETER_CALIBRATION_PROPOSAL 的全部待批准参数及所需资料见packing-station-evidence-matrix.json。任何未知参数均无正式默认值。
