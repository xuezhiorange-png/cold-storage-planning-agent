## 已确认的第一阶段成因

1. `GlobalModel.__init__` 对服务器 P1 的 `FLEXIBLE_RECTANGLE` 使用整数毫米长宽，
   `area >= required_area`。Changing 的 40m²是下界，不是固定长宽，也不是上界。
   40942×976mm 面积不够，40942×977mm 满足下界，所以短边977mm在该长边下合法；
   这不是工程批准的室内净宽。没有 P1 规则要求它必须如此狭长。
2. `StageBFairSearchSolver._final_guidance` 使用
   `apply_wall_alignment_guidance`：最近其他房间平行墙偏差之和加 X/Y 房间跨度。
   它没有直接表达三个辅助房间的最差长宽比。外包跨度也不等于建筑实际周长或孔洞。
3. `OrToolsGlobalCompositionSolver.iter_solutions` 的普通 Fair 路径没有调用
   `_GuidedInvocation`。名为 `ALL_ROOM_GEOMETRY_HINT` 的预备阶段本身不等于
   已启用半周长引导；既有半周长实现位于独立的 construction guidance 路径。
   因此不能仅根据阶段名称声称原最终模型已经优化过房间比例。
4. `_run` 在第一阶段首个可行解处停止；warmup Hint、通道决策顺序、结构 Handoff
   和有限资源共同影响实际赋值。墙线目标存在不等于已求得该目标的最优解。
5. 原 `_BalancedNative` 只有在独立工程接受并保存基线后才引入 Minimax。
   改善阶段开始得再早，也无法让已保存的第一阶段几何事后变成另一套基线。

已确认的是这些代码路径及实际被接受的赋值；尚未证明 Access/MUST 强制产生狭带，
也没有证明相同 Handoff 存在比例更好、零孔洞且人员路线不恶化的替代布局。
不能将有限搜索未找到替代解解释为其不存在。

### 可行域与验证边界

对每个正整数物理赋值，short/min、long/max、整数分子、ceil比例和worst均有唯一
合法扩展。删除软目标后投影回原物理变量域完全相同。已有正域与int64检查继续
fail closed，不把不支持的域裁小。测试穷举六个1..3变量共729个原赋值，全部且仅一次
保留；这与数学总定义证明相配合，不是整厂求解或完整工程验收。

两种微型合法赋值的对照验证墙线偏好与Minimax偏好确实不同；该合成例不能证明
真实工厂替代布局存在。两边都实际使用原首解停止与单次Native调用，不以额外优化
时间冒充首阶段效果。R4 测试还验证同模型代理复用、UNKNOWN、预算拒绝、旧策略
绑定拒绝、基线保留、精确孔洞切除及固定输入的模型/见证可复核性。

### 仍需 Owner 审核的取舍

Minimax 只针对最差房间，可能扩大柔性房间面积，可能牺牲墙线协调、人员路线或
建筑轮廓。首解停止与 warmup Hint 仍可能产生非最优狭长房间。R4不保证真实产出
变好、不保证排除孔洞，也不保证资源效率提高。原代理定义的模型扫描及其Work
计费被提前到第一阶段，固定预算下也可能影响首个有效候选的获取，不能隐瞒这一
成本。人员路线、周长、转折和凹角仍使用
原九项实测比较；面积仍只作事实，不偷偷加入或移除 Pareto 指标。

这些风险必须由后续独立授权实验验证，不能用本轮合成测试代替。
