## Minimal safe topology improvement and its limit

New opt-in native enumeration uses an **exported union input equivalence** cut.
It fixes every physical room `(x,y,width,depth)`, every Packaging case activation
and its active corridor centre, every ordinary corridor activation and all six
points of every active corridor. Packaging face coordinates are determined by
the room faces and selected side. These values determine the actual simplified
export path and its strips/turn envelopes, not an approximate symbolic bbox.

Thus equal cut values imply exactly the same rectangle union and the same
certified invalid topology. Direct Shared Edge Portal centres and redundant
nominal rotation encodings do not add building area and are intentionally not
part of this cut. A changed room, active route, Packaging case or corridor point
remains searchable; another corridor filling the void is not incorrectly
excluded. No-good scope, actual variable indices/names/values and exact topology
certificate remain auditable and charged. UNKNOWN never produces a cut.

This safely eliminates some equivalent invalid encodings. It does **not** prove
that the sixteen historical, physically different failures would disappear, or
that holes are prevented in advance. Exact union, original Footprint derivation,
Site and the unchanged application engineering oracle still decide eligibility.
This is the deliberately limited safe improvement allowed when a stronger
pre-filter is not proven. The old native default and Stage-A first-result path
use the original cut when no new callback is supplied.

## Opt-in bounded coverage schedule

New internal bootstrap entry:
`generate_fair_multi_solution_global_layout_pool`. Existing entries retain their
behavior. Six server-derived handoffs keep their original order and hard domains.
One composition admission/preparation is used per handoff; there is no second
`begin()`, mid-composition resume or refreshed ledger.

At each handoff, divide remaining pool native reservation, remaining 85-second
elapsed reservation and remaining 600000-work reservation by handoffs remaining.
Native calls are clipped to the remaining local native/time quantum; each of the
four hint calls is additionally capped at one eighth of the native share, leaving
room for the final model. Checked-assignment quantum is floor(remaining checked
assignments / remaining handoffs), at least one while assignments remain.
If all consume their checked share, the sequence is **3,3,3,3,4,4**, not twenty
attempts for the first handoff. Unused shares carry forward deterministically.

Quanta are additional scheduling bounds **between native calls**, not Authority
caps: model preprocessing/application validation may overrun a local time/work
share, but remain fully charged and subject to all original shared guards. Global
resource/history/Host interruptions still stop the pool; local share exhaustion
advances to the next handoff and is neither INFEASIBLE nor engineering PASS.
Nothing guarantees that every handoff finishes a final solve before a real shared
limit. Shorter hints may reduce feasibility yield; only a newly approved real
execution can quantify that tradeoff.

The versioned policy and hash are in `application/stage_b_search_policy.py`.
The new ScheduleHash hashes the original six-handoff hash **and** this policy hash.
Existing durable admission compares it to the approved Owner decision before
any solver call: old grants cannot admit the new schedule. No new grant/UUID or
registry slot is issued here. Future approval must bind the new committed source,
dependency files, policy and schedule. Native 100 seconds / elapsed 180 seconds /
1200000 work / 512 MiB / Host 20000 remain unchanged, as do replay reserves and
the existing twenty-checked-per-pool and hundred-total-native-call contracts.
